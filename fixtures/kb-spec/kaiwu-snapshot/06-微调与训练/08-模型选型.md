# 模型选型：0.5B → 4B/8B 的基座对基座对比

> 2026-11-03。dev120（n=120），同一 v4 prompt、greedy + seed 0、同一后处理与评分器；MLX 侧用枚举白名单裁决替代 outlines。完整报告：`evals/model-selection-report.md`。

## 结论

**主选 Qwen3-4B-Instruct-2507（MLX 4-bit，2.29 GB）：dev120 全字段 0.5417（65/120），比现基线 Qwen2.5-0.5B 的 0.2917（35/120）高 25.0 pp；McNemar p=3.6e−05、95% CI [0.1417, 0.3583]、超过配对 MDE 0.1631，判定显著。Qwen3-8B 同分（Δ=0、p=1.0）但体积 2 倍、延迟 1.8 倍，只作备选。**

适用条件（不满足就不要套用这条结论）：

- 结论覆盖的是**基座对基座**，不含任何微调；0.5B 的 LoRA 增益（dev120 +0.367～+0.408）是另一件事，不能与 25 pp 相加或对撞。
- 只在 dev120 上有数（n=120）。test2 已于 2026-11-03 消耗，4B 基座**没有**独立 held-out 估计。
- 延迟与内存是 M5 Pro / 48 GB / MLX 0.32.4 实测，换硬件不保证同比例。
- 8B 的结论依赖“显式关闭 thinking”；默认模板下同一模型只有 0.017（2/120），是口径错误不是模型差。

## LoRA 可行性（只验不训）

| 项 | Qwen3-4B | Qwen3-8B |
|---|---|---|
| 注入/保存/重载 | 通过 | 通过 |
| adapter | 2.5 MB | 3.25 MB |
| step 中位数（768 token） | 0.528 s | 0.902 s |
| epoch（**外推**） | 145.8 s | 249.1 s |
| 训练峰值 | 5,555 MiB | 7,933 MiB |

- 4-bit 基座 + LoRA 有实测支撑；bf16 基座 LoRA 未实测（bf16 权重 16.38 GB，超出下载预算），只能按参数量推算约 22～27 GB。
- 阶段二（4B LoRA）未执行：按实测成本核算需 33～45 min，超过 30 min 上限，且仓库无现成 MLX 训练器。

## 风险

- 4B/8B 的 LoRA 训练质量未验证；4-bit 与 bf16 LoRA 的精度差未实测。
- 未下载的 7 个候选是“未测”，不是“更差”。
- 0.5B + LoRA 在 dev120 上（0.633/0.675/0.650）高于 4B 基座 0.5417，但偏差已知，**不能据此宣布 0.5B+LoRA 更好**，需要 4B LoRA 同口径对比。
