# 分类与优先级映射

> 全库 34 篇主题文档的单一分类表：每篇的类型、优先级、依赖与被依赖关系，以及归档规则与校验器盲区。

## 这张表解决什么

这张表是整改与维护的共同依据，回答三个问题：这篇文档属于哪一类、做决策时是否必读、它依赖谁又被谁依赖。后续新增文档先在这里登记，再写正文并在 README 加链接。

**优先级不等于阅读顺序。** 优先级回答“做决策时该不该读”；阅读顺序回答“新人从哪篇开始”。一篇进阶文档可以排在阅读路径最后，同时是 P0。

## 类型定义

- **结论类**：给出已经验证的结论与适用条件，读者据此做判断，例如基线表现、模型选型、任务定义。
- **方法类**：给出可复用的做法与配置，例如统计检验方法、训练配置、检索与门禁流程。
- **决策记录类**：记录某个时点的取舍、备选方案与理由，重点在“为什么这样定”。
- **数据与口径类**：定义数字怎么算、数据集怎么划分、标注怎么判，是其他文档引用数字的前提。
- **归档类**：历史过程或被后续结论覆盖的记录，保留可追溯性，不与当前结论混排。

## 优先级定义

- **🔴 P0**：做决策必读。当前基线、评测统计口径、模型选型、当前默认配置、任务定义。
- **🟡 P1**：子系统说明与专题实验。理解某个模块需要读，但不直接决定默认配置。
- **🟢 P2**：历史过程、已归档周报与已被覆盖的结论。只在追溯时需要。

## 归档规则

1. 状态为 `已归档` 的文档一律放在 `99-归档/`，文件名保留原编号与标题，仅重编序号。
2. 归档不删除正文，正文首行保留“迁移去向”说明；历史周报原文在 `evals/` 内保留，不进知识库。
3. 当前结论文档不得把归档文档当作唯一依据；引用时必须同时给出替代它的当前文档。
4. README 中归档文档归入“归档索引”一节，不进入“建议阅读顺序”。

## 校验器已知盲区（未检查及原因）

- **夹子标题缺正文**：`## A` → `### B`（无正文）→ `## C`。校验器只比较相邻同级标题，A 与 C 之间隔着 H3 B，不算相邻同级，因此抓不到。要覆盖需引入“父级子树是否为空”的新判据，会与规范定义的 H3 冲突，故不做，交由评审自觉。
- **元数据组豁免 README**：索引页不是文档，M1–M4 整组跳过。
- **文本风格只扫散文**：代码块、行内代码、链接目标、裸 URL、书名号内容先剥除，这些区域用词不查。
- **链接文字“描述性”靠黑名单**：只拦 `点击这里`、`点击此处`、`本文档`、`更多`、`详见`，无法判断其余文字是否真的描述目标。
- **内容与结论的一致性不校验**：校验器只看结构与元数据，数字是否与来源文件一致仍需人工复核。

## 校验器已知边界

- **只保证结构、元数据、链接与风格合规，不保证内容一致。** 数字是否与 `evals/` 来源一致、结论是否仍成立，机器不判，需人工复核。
- **可判定范围**：S 组扫描项目根与分类目录下的全部文件与目录（含图片、`notes.txt` 这类非 Markdown 文件）；M 组校验 frontmatter 是否为扁平标量；L-1 对包括图片在内的所有站内链接要求 `./` 或 `../` 前缀；H-2 把首个标题纳入层级判定。
- **规范文档自身不自洽**：`kb-general-spec.md` 写“合计 17 错误 + 9 警告 = 26 条”，但正文只列出 24 个规则编号（S-1…S-4、M 组 4 条、H-1…H-5 与摘要、L-1/L-1a/L-2…L-6、T-1…T-3）。按编号是 24 条（15 error + 9 warning）。校验器把 M 组拆为 6 项、H 组拆为 6 项后得到 26 条（17 error + 9 warning），与“26 条”的总数一致、与“24 个编号”不一致；本库按实现口径记 26 条，待规范维护方统一编号。
- **语义判断不在范围**：链接文字是否准确描述目标、标题是否贴切、正文结论是否自洽，均需人工评审。
