## ADR-0011：事实与推断分层——工具层零 LLM，归纳只在编排层（2026-11-12，M5）

**背景**：技术栈、目录结构、任务进度这类事实如果被 LLM"归纳"，错误会以自信的语气混进事实。

**决策**：
- `tools/` 全部是确定性代码：清单解析、SQL、图算法，每条事实带 source 字段。
- LLM 只出现在两处：`llm/answer.py`（证据归纳）与 `llm_draft.py`（草案生成），且提示词强制"只用证据、证据不足明说、建议单列并标注是推断"。
- 任务依赖图（`task_graph.py`）的可执行/并行判定用确定性图算法，"不让模型猜"。

**理由**：LLM 幻觉无法根除，只能隔离——把幻觉关进"明确标注的推断"笼子里。

## ADR-0012：LLM 后端双模——OpenAI 兼容优先，本地 MLX 兜底（2026-11-12，M3→M6）

**决策**：`LLM_BASE_URL + LLM_API_KEY` 存在走任意 OpenAI 兼容服务；否则加载本地 MLX 模型（默认 kaiwu 的 Qwen3-4B-Instruct-2507-4bit）。

**理由**：查询扩展与文档草案是辅助路，不需要顶配模型，本地 4B 够用水零成本、数据不出机；需要更好质量时改环境变量即切换，不改动代码。`backend_name()` 让当前后端在回答中可见（可审计）。

## ADR-0014：评测方法论沿用 kaiwu/evals（2026-11-12，M3）

**决策**：100 题 JSONL 用例集 + recall@k/MRR + McNemar 配对精确检验 + 冻结基线对比；判定为 Top-5 证据的 path/symbol 包含 gold 关键词。

**理由**：方法论直接从 kaiwu 项目移植，保证跨项目可比；McNemar 只看"翻转题"（配对样本），100 题规模下比独立样本检验功效更高、更不容易把噪声当收益。判定用"关键词包含"而非 LLM 裁判：便宜、确定、无裁判偏差。

**已知边界**：`evals/README.md` 记录 5 题已知未命中（q044/q057/q076/q078/q080），判定为真实检索短板而非评测噪声。

## ADR-0015：评测版本用内容指纹而非 Git 元数据（2026-11-13）

**决策**：评测结果记录完整检索配置、模型名、查询扩展缓存 SHA-256、检索源码 SHA-256、索引文件内容 SHA-256 和题集 SHA-256。对比要求题集完全相同；旧结果缺元数据、索引变化或实现变化必须告警。

**理由**：当前工作副本不应依赖 Git 才能复现实验。文件内容哈希比提交号更直接地描述实际运行语料与实现，也避免把“有提交号”误当成“配置完整”。

**验证集边界**：新增 12 题 `cases_holdout.jsonl`，不参与 v1–v7 调参；冻结配置后只验收。若根据其结果继续调参，必须另建验证题。

## ADR-0016：复合扩展词子串通道与评测污染清理（2026-11-13，v7）

**采纳**：完整复合扩展词增加符号子串通道（0.6/limit 3），使 `report_json` 能挂接 `print_report_json`。纯单词不走该通道，避免 `migrations` 命中 `MapMigrationStore` 的跨驼峰拼接片段。

**数据**：100 题 recall@1 0.77→0.78、recall@5 0.95→0.96、MRR@5 0.8322→0.8413；改善 1 题、恶化 0 题。弱扩展候选保留与“数据库”路径提示因无净收益或引入噪声而拒绝。

**索引边界**：评测题、路由题、冻结基线、评测结果和 `.pytest_cache` 均排除。曾观察到跨项目查询 Top-5 被 dev-kb 自身的题目与旧基线占据，这类自我引用既是检索噪声，也是评测泄漏。

## ADR-0017：MCP 只读且项目范围显式化（2026-11-13）

**决策**：`mcp_server.py` 通过 stdio 提供 `index_status` / `search` / `read_source`，不暴露同步或文件写入；搜索只使用已有查询扩展缓存，不调用 LLM、不写缓存。`read_source` 拒绝绝对路径和目录越界。

**项目路由**：只有唯一识别项目名才自动限定；未识别或多项匹配返回候选，必须显式指定项目或 `all_projects=true`。路由评测单独衡量覆盖率、错误路由与歧义保护，不能用显式传入项目名的检索评测替代。

**理由**：减少文件扫描不能以扩大数据访问范围或隐式跨项目泄露为代价。当前路由基线错误路由为 0，后续提升覆盖率时保留这一约束。
