## ADR-0027：知识源规范重新定义为知识源接入契约（2026-11-15）

**背景**：M7 建的"知识库规范"是 123 条文档内容规则 + 提案式写入工作流。核对后
发现：它对检索器的行为约束是 **0**——`ingestion`/`indexing`/`tools`/`llm` 对它零
引用；`heading_path` 存了却只用于回显；frontmatter 无结构化字段；分类目录无字段。
它既没有锁住兼容面，又额外造了一套 Markdown 解析器。

**决策**：把"知识库规范"重新定义为**知识源接入契约**：规定任何知识源接入检索器时
必须交代什么（提供哪些结构字段、内容边界在哪、中文意图对应哪些路径），检索器只认
交代、不认具体是哪种库。文档内容规则全部删除。

**理由**：兼容面爆炸的根源不是文档长得不一样，是**每来一种库就要在检索器里写一个
特例**。契约必须在接口层才能锁住它；而"文档写得规不规范"与检索能力无关。

**代价**：契约本身需要一套规则与检查器（7 条，见 ADR-0028 与规则文档）；换来的
是新增知识源不需要改检索器。

## ADR-0028：知识源不做类型枚举，声明结构提供方（2026-11-15）

**决策**：知识源不声明"类型"，只声明**提供哪些可选结构字段**（`provides`）：
`heading_path` / `category` / `doc_role` / `aliases`。检索器按声明消费，缺字段即降级，
不拒绝接入。

**理由**：类型枚举恰恰是要避免的东西——每加一种库就多一个枚举值、多一套 adapter
逻辑。能力声明是正交的：新增一个库不需要新增任何枚举。

**代价**：规则按"适用条件"判定，源没声明对应字段时相关规则不适用——比"每条规则都
要判一遍"复杂一点，但这是同一套契约能覆盖代码库与文档库的前提。

## ADR-0029：契约字段落到 chunks 表，标题链进 FTS 与独立通道（2026-11-15）

**决策**：`chunks` 表新增 `category` / `doc_role` / `aliases` 三列；`heading_path`
进入 `chunk_fts` 的可检索文本（与正文同等权重），同时另建 `chunk_headings` 索引
支撑**独立的标题链召回通道**（权重 0.7）。

**理由**：契约字段必须有下游消费者，否则又是"存了不用"。独立通道的意义是可单独
调权、单独归因——评测里能看到它贡献了多少 recall，这是"一次只加一个变量"的延续。

**代价**：需要重建 FTS（不重算向量）。新增通道可能挤占既有通道的排序位，必须过
McNemar 配对检验。

## ADR-0030：文档写入门禁整体移出项目范围（2026-11-15）

**决策**：删除提案/审批/落盘闭环（`proposals/`、`docs_cli`、kb_spec 写侧、两个 MCP
client）、M4 Spec 结构化（`specs/`、`spec_cli`）、以及 18 个一次性脚本与 10 个
`verify_*.sh`。

**理由**：文档更新属于代码开发与知识库维护的工作，不属于检索问答 Agent。这批代码
的复杂度主要来自"对存量知识库做一次性批量迁移"（before_sha 乐观并发、README 增量
重放、stale 预检），不是来自长期能力。

**代价**：agent 未来要写文档时得重新做（但那时的需求形态会更清楚）。

## ADR-0031：frontmatter 不作为任何契约字段的来源（2026-11-15）

**决策**：`doc_role`、`aliases` 等字段只来自声明与调优表，**不从文档 frontmatter
读**。

**理由**：frontmatter 覆盖率在五个库之间是 0%（repository-manage）到 92%
（ai-video-kb），键名全中文（`状态`/`最后更新`/`下次复核`）且与检索无关；写侧已
移出项目，我们不会去改用户的文档。让检索能力依赖一个不打算写的字段，是把问题换个
地方埋。

**代价**：术语别名要人工维护一份表（`tuning/<source>.yaml`）。

## ADR-0032：契约字段的唯一事实源是 SQLite（2026-11-15）

**决策**：Qdrant payload 只存标识与定位信息（project/path/symbol/行号/source_type），
**不复制**契约字段。

**理由**：检索层本来就用 chunk id 回查 SQLite 取字段，payload 里再存一份没有功能
价值；Qdrant 的 `set_payload` 只接受"一个 payload 配多个点"，逐点更新 4 万多个点
要 4 万次调用；替代方案（带向量回写）有损坏 collection 的风险。

**代价**：向量库侧无法按 category/doc_role 过滤。要做的话应先有明确需求。

## ADR-0033：切块器修正——标题链是真实链，frontmatter 不是标题（2026-11-15）

**背景**：核对索引时发现两个 bug。

1. `heading_path` 数组长度**恒为 1**（964 个块全是单元素）——收集祖先标题的循环在
   第一次迭代就 break（`headings[:idx+1]` 的最后一个元素就是它自己）。父标题信息
   全丢：问"核心架构"命中不了"### 模块"这种子节。
2. Markdown 解析器不认识 YAML frontmatter：`状态: 稳定` 被 setext 规则当成二级标题，
   于是 frontmatter 的最后一个键值变成一条假标题，frontmatter 块因此没有标题信号。

**决策**：标题链改为"祖先标题（层级严格更浅）+ 自身标题"；识别 frontmatter 区间并
把其中的伪标题换成文档的首个真实标题。

**理由**：这两个 bug 让"标题链"这个契约字段名不副实，也让契约规则 R-02 在度量切块器
而不是度量语料。

**代价（2026-11-16 修订）**：历史索引中的错误 `heading_path` 需要全量重建才能修复。
`sync_cli --backfill` 只根据已有 chunks 回填 `category` / `doc_role` / `aliases`，
不读取源文件，也不能重新推导标题链。

## ADR-0034：全局排除表只放跨项目通用项（2026-11-15）

**决策**：把 `models`、`notebooks`、`kb_corpus*` 从全局 `EXCLUDE_DIRS` 移到 kaiwu
自己的 `extra_exclude_dirs` 声明。

**理由**：全局表里的项目专属项会让这条规则对所有项目生效——那正是契约要消除的跨
项目耦合。

**代价**：项目特有的排除项要写在该项目的声明里（多一处配置）。

## ADR-0035：规模红线（2026-11-15）

**决策**：设 6 条红线防止子系统重新长回来：README 能力表 ≤ 6 行；非检索主链代码
≤ 检索主链的 100%；新增顶层目录必须在 README 回答"它站在检索链条哪一步"；
`evals/results` + `evals/baselines` ≤ 2 MB；仓库 tracked ≤ 3 MB；每个知识源的注册表
声明 ≤ 30 行。

**理由**：删掉的东西会再长回来——第一个人长出来时的机制是一样的。红线是最便宜的
复发防护。

**代价**：红线需要定期核对（可做成 CI 检查）。

## ADR-0037：全局硬编码路径表按源分发后删除（2026-11-15）

**背景**：检索器里有一张全局 `_PATH_HINTS` 表（20 条"中文意图 → 目录名"），
对所有项目生效。它只对 Laravel 类目录有效，对文档型知识库几乎无用，且带一个拼写
错误（`"中间件": "middleware"` 少个 m，实际匹配的是 "iddleware"）。

**决策**：把它的条目**按源分发**到各库的 `tuning/<source>.yaml`，逐条用本库实际
内容过滤（片段匹配不到任何路径的丢弃），然后删除全局表。

**理由**：全局表与知识源声明是同一件事的两种写法。分布之后，"中文意图 → 本库路径"
这条知识就归它该在的地方——每个库自己的结构声明里。

**代价与过程**：取代它花了三轮评测测量，且中途两次更差：

| 尝试 | r@1 | r@5 | MRR | 结论 |
|---|---:|---:|---:|---|
| 全局表（改造前） | 0.780 | 0.960 | 0.8413 | 对照 |
| 按源写声明（目录级片段） | 0.760 | 0.950 | 0.8230 | 退化 |
| 全局表 + per-source 叠加 | 0.780 | 0.940 | 0.8335 | 退化（稀释） |
| **按源分发短片段后** | **0.800** | **0.960** | **0.8527** | 采纳 |

关键差别是**片段粒度**：全局表用 `api`、`Auth`、`Middleware` 这类短片段，能同时
匹配到文件名（`ApiController.php`）；按目录写的映射（`src/renderer/store`）匹配不到
文件名，命中率因此低一截。逐条按本库实际内容过滤后，per-source 声明全面不劣于全局表
（r@3 +0.01、MRR +0.0014、McNemar 零退化）。

**附带修掉**：意图映射的语义此前不一致——检索用 `path LIKE %片段%`，而 R-03 按
"字面路径存在"判定，`migrations` 这类片段会被误判为不存在。R-03 改为与检索同口径。

## ADR-0036：契约门禁接入 CI（2026-11-15）

**决策**：`.github/workflows/ci.yml` 两个 job——契约门禁（只装 PyYAML，校验 dev-kb
自身满足契约，用 `projects.ci.yaml` 把仓库根登记为一个知识源）与轻量测试集；
`scripts/contract_check.sh` 提供本地入口。

**理由**：ADR-0026 声称有 CI 门禁，但仓库里没有 `.github/`，那个门禁从未真正生效。
而且真实 `projects.yaml` 不入库，CI 里没有本地知识源可查——能自动检查的是"dev-kb
自己的文档要满足它自己定的契约"。

**代价**：索引级规则（R-02/R-05/R-06）在 CI 里没有索引可用，因此不适用；CI 只能
守住声明层。声明层恰恰是最容易腐化的一层。
