# 评测指标口径

> 定义 kaiwu 评测里每个指标算什么、不算什么，以及读这些数字时必须记住的统计与规则局限。

## 主指标

- `json_valid`：Pydantic `Ticket` 校验通过，包含枚举合法与订单号形态；每条最多一次修复重试。
- `all_fields_exact_rate`（全字段）：6 个字段全部按规则通过。
- `structured_all_rate`（结构字段）：排除 summary 的 5 个字段全部通过。
- `summary_keyword_rate`：summary 关键词组匹配，每组命中任一词即通过。
- `field_accuracy`：逐字段准确率。
- `avg_latency_s`：平均单条耗时。

来源：`evals/eval.py`、`evals/test-milestone-1-report.md`。

## 评分约定

字符串 strip 后转小写比较；空串按 null 处理；“无”“未知”仍按错误处理。summary 允许措辞差异，用关键词组而不是逐字匹配。来源：`docs/env.md`、`docs/labeling-guide.md`。

## summary 规则的局限

关键词匹配只能验证要点是否覆盖，不能验证事实是否一致或有无编造。可能出现“关键词都对但语义错了”的假阳性，也可能出现同义改写未命中的假阴性，例如“发票未开”未命中期望词“没开”。因此报告里 summary 只报关键词通过率，不当作语义正确率。来源：`evals/week1.5-report.md`。

## 生成与可复现口径

从 week4 起，所有用于结论的评测必须满足：

- `do_sample=False`（greedy），并显式清空 temperature、top_p、top_k，不沿用模型自带的 `generation_config.json`；
- 固定 `seed`（默认 0）、固定 device 与 precision（**2026-11-03 起默认 MLX + 4-bit**，模型为 Qwen3-4B-Instruct-2507；历史 bf16 + MPS 路径可用 `--backend hf --model-path qwen2.5-0.5b-instruct` 覆盖）；
- 每次运行写 manifest，记录模型 revision 与权重 hash、库版本、prompt 与 schema hash、数据 hash、解码参数、评测规则版本与时间。

同一通道的 greedy 是逐字符可复现的，跨通道（MPS bf16 与 CPU float32）不是逐位一致，约 3/40 条判定会翻转。因此“复现”只能指同一通道内复现。细节与证据见 [评测稳定性与统计检验](./03-评测稳定性与统计检验.md)。

## 2026-11-05 补充：cohort、order_id 三档与两遍生成

**cohort 口径**（`evals/baseline.json` 的 `cohorts`）：

- `old-30`：30 条旧样本，只有 5 个结构化字段计入 `all_fields`（排除 summary）；all_fields 0.933。
- `new-90`：90 条新样本，6 字段（含 summary）；all_fields 0.800，**对外主口径**。
- `all-120`：120 条合并；混合口径——old-30 用 `structured_ok`（5 字段），new-90 用 `all_ok`（6 字段），`all_fields_scope="mixed"`；all_fields 0.833。**不可当统一基线**，也不能与 new-90 的 0.800 直接相减。

**summary 分母 91**：dev 120 中只有 91 条有 `expected.summary` 关键词组；29 条 old 样本只有 `summary_text`，没有关键词槽。因此 `summary_keyword_rate` 分母是 91，old-30 的 summary 不能评估。

**order_id 三档**（`evals/eval.py` 的 `order_id_breakdown`，只增加报告字段，不改判定）：

- 最终管线 120/120（含后处理回填）；
- 纯模型 raw 在 gold 非空的 106 条中非空 100 条，其中正确 99 条、非空错误 1 条；
- gold 为 null 且 raw 为 null 的 14 条，null-null 免费通过。

**两遍生成**：默认先跑主 v4 prompt 全字段抽取，再按机械判据对 `summary` / `product` / `customer_name` 做定向重写；每次只改一个字段，每字段最多一次。因此同一条 case 的分数依赖 `--summary-retry` / `--field-retry` 开关，跨开关的数字不可直接相减。细节见 [回归门禁与阈值](../08-应用层/03-回归门禁与阈值.md) 与 `docs/env.md` 第 6 节。

## 统计口径

week4 修订：不再用单次点估计或多次采样的均值/极值判断两个配置优劣，统一用配对检验。

- 点估计必须配 Wilson 95% 区间；比较两个配置必须用同 case 的配对结果。
- 检验用 McNemar 精确检验（双侧），CI 用配对 bootstrap（默认 10000 次）；工具见 `evals/paired_stats.py`。
- 报告必须给近似最小可检测差异（MDE）。n=20 约 0.27 至 0.37，n=40 约 0.23 至 0.31，n=55 test2 的配对 MDE 约 0.185，n=120 抽取配对约 0.113、检索配对约 0.093 至 0.104；小于对应 MDE 的差异在本项目中不作为结论。来源：`evals/paired_stats.py`、`evals/week8-report.md`、`evals/test2-report.md`。
- p 大于 0.05 时写“不能判定有差异”，不写“无差异”，也不写“显著更差/更好”。

历史 Wilson 区间（week1.5，旧 test 20 单次口径）：6/20=0.30 对应 [0.145, 0.519]；8/20=0.40 对应 [0.219, 0.613]；5/20=0.25 对应 [0.112, 0.469]。当时 0.30 与 0.25 的差异不能判定优劣。来源：`evals/test-milestone-1-report.md`、`evals/week4-report.md`。

## 失败归因分类

报告使用五类归因：模型能力、标注口径、评测规则、后处理、约束解码引入或放大。同一条样本可以多因，归因依据是原文、指南与预测结果，不是自动分类。来源：`evals/test-milestone-1-report.md`。
