# 标注口径指南

> 把 `docs/labeling-guide.md` v1.0 的判据压缩成可查阅的要点，供标注、复核与失败归因时对齐口径。

## 标注顺序

按 `product` → `issue_type` → `order_id` → `customer_name` → `urgency` → `summary` 执行。先定 product，因为 issue_type 依赖“客户在为什么东西提诉求”。

## 全局约定

1. 缺失一律 `null`，不写空串，不写“无”“未知”“N/A”“待定”。
2. 只抽取原文出现的信息，不做常识补全，不编订单号。
3. 原文优先：除枚举字段外，取值应是原文的字面内容或最小名词形式，不做同义改写。
4. 一条文本只产出一个工单；多个诉求时取与当前要处理的那件事直接相关的。

来源：`docs/labeling-guide.md`。

week8 新增的 80 条 dev（c218–c297）仍按本指南 v1.0 判定，未改判据；难度提高只体现在文本干扰与边界密度，不体现在字段定义。来源：`evals/week8-report.md`。

## 字段要点

| 字段 | 关键判据 |
|---|---|
| customer_name | 2 至 4 字人名，或“姓氏加称谓”；称谓保留完整，如“王女士”不缩成“王”；“客户”“会员”属指代，填 null |
| product | 交易标的；保险、机票、酒店预订、会员服务、宽带等抽象服务必须填；物流、快递、发票、售后属履约过程，填 null |
| issue_type | 动作优先于情绪；退货优先于换货，换货优先于维修；投诉只在没有具体动作诉求且明确不满时使用 |
| urgency | 今天、立刻、马上、明天就要出行等 24 小时内硬约束为高；2 至 7 天窗口为中；“尽快”“比较着急”为中；“不急，下周安排也行”为低 |
| order_id | 字母前缀加 8 位以上数字，或上下文明确为订单号的 8 位以上纯数字；只复制原文；手机号、快递单号、会员卡号不算 |
| summary | 不超过 30 字，包含对象、问题、诉求；不写姓名、订单号与时间承诺 |

## 争议口径

| 争议 | 结论 |
|---|---|
| 保险、机票、酒店预订算不算 product | 算；判据是“客户为它付了钱吗” |
| 积分、优惠券、余额 | 默认 null，只有明确购买积分包或充值包时才算标的 |
| 部件与症状 | 不并入 product，截断到主体，如“笔记本电脑风扇异响”填“笔记本” |
| 其他与咨询的边界 | 要后台动这笔单子的归其他，只想知道规则的归咨询 |
| “希望尽快答复” | 中，不是高；“尽快”没有截止时间 |
| “这周内就行”同时出现“不急” | 中，2 至 7 天窗口优先于主动延后 |
| “我是刘敏”“赵六的订单” | 取“刘敏”“赵六” |
| “客服小李”“张先生” | 前者为坐席，填 null；后者保留称谓 |

来源：`docs/labeling-guide.md`。

## 已知局限

- summary 用关键词组评测，只能验证要点覆盖，不能验证事实一致或有无编造；
- 标注由单人执行，第二标注者与 Kappa 未建立，一致性未确认；
- 指南规定改动必须升版本号并写变更说明，当前版本为 v1.0。
