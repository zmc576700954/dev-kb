# 数据构造与泄漏检查

> 记录数据集从 217 条 v3 扩到 297 条 v4、再到 537 条 v5 的构成、划分、泄漏检查方法与已知限制，说明 week8 新增 80 条 dev 样本补了什么、v5 为什么从 train 移除 40 条旧 dev，以及 dev 120 为什么仍不能当泛化。

## 数据规模与构成

- v2：180 条（c001 至 c180），旧 60 加新增 120。
- v3：217 条（c001 至 c217）。新增 37 条：25 条 sealed test2（c181 至 c205）与 12 条 train 投诉类（c206 至 c217）；v2 的样本与标签未改动。
- v4：297 条（c001 至 c297）。week8 只新增 80 条 dev 样本（c218 至 c297），`source=synthetic-w8`，每条带 `rationale` 与摘要关键词组；train/valid/test2/dev2 沿用 v3，未改动。
- v5：537 条（`evals/cases_v5.jsonl`）。在 v4 基础上移除 train 中与 dev 重合的 40 条旧 dev40，补 220 条合成与 20 条改写（共新增 240 条），得到 train 302 / valid 40；dev120、test2 55、dev2 20 的 id 与标签未改动。配比见 `evals/data-mix-v5.json`，泄漏检查见 `evals/leakage-check-v5.json`。来源：`scripts/build_cases_v5.py`、[训练数据 v5 与工程化配置](../06-微调与训练/04-训练数据v5与工程化配置.md)。
- 新增样本按 `docs/labeling-guide.md` 人工判定，逐条写 rationale；`evals/cases_v3.jsonl` 中 c181 至 c217 与 `evals/cases_v4.jsonl` 中 c218 至 c297 的 rationale 均非空。

v2 新增 120 条的维度分布见 `evals/week2b-report.md`。v3 新增 37 条优先补三类短板：

| 维度 | v3 新增条数 | 说明 |
|---|---|---|
| 投诉 / 追责 | 24 | 12 条进 test2、12 条进 train |
| urgency 高 | 15 | 全部进 test2 |
| product 应为 null | 13 | 全部进 test2 |

三类可重叠，因此 25 条 test2 新增样本中三类合计命中 40 次。来源：`evals/expansion_c_summary.json`、`scripts/expand_dataset_c.py`。

机械校验：217 条 id 与 input 无重复；非空订单号全局唯一（新增样本使用 QB 前缀）；姓名是原文子串且不与旧 60 条姓名重合；summary 不超过 30 字且每个关键词组至少命中一个词。来源：`scripts/expand_dataset_c.py`、`scripts/check_leakage.py`。

## v4 新增 80 条（week8）

新增样本 c218–c297 覆盖 week7 已暴露的失败模式：抽象服务名被写成品牌、“X的订单/我买的”里的姓名位置、其他 vs 咨询边界、无时限的紧急度、部件不并入 product、product 应为 null。难度上 **51/80 标为 hard**（旧 dev 40 的 hard 计数为 0），新增样本平均原文 54.0 字（旧 dev 40 为 38.7 字）。

dev 120 的分布（旧 40 + 新 80）：

| 维度 | 数量 | 说明 |
|---|---|---|
| issue_type | 退货 29 / 咨询 25 / 维修 19 / 其他 17 / 换货 16 / 投诉 14 | 六类均有覆盖 |
| urgency | 中 52 / 高 33 / 低 35 | 中为多数，高与低接近 |
| product 为 null | 14 | 占 11.7% |
| customer_name 为 null | 11 | 占 9.2% |
| order_id 为 null | 14 | 占 11.7% |

来源：`evals/week8-audit.json`、`evals/week8-report.md`。

## 划分

| 集合 | 条数 | 组成 | 用途 |
|---|---|---|---|
| train（v5） | 302 | 旧 train 82（v4 的 122 移除 40 条与 dev 重合样本）+ 新增 220 | LoRA 训练；与 dev/valid/test2 严格不重合 |
| valid（v5） | 40 | 旧 valid 20 + 新增 20 | 验证 loss 与早停 |
| test2 | 55 | v2 test2 30 加新增 25 | 已消耗（2026-11-03 held-out 验收），此后只作回归 |
| dev2 | 20 | 旧 test 20 | 降级开发集 |
| dev（v4/v5） | 120 | 旧 dev 40 加新增 80 | 抽取/检索配对对比、回归门禁；错例参与了 v5 构造，增益偏乐观 |

v5 的 train、valid、dev、test2 两两无交集，完整 id 在 `evals/split_v5.json`；回归门禁仍用 v4 的 dev 120（`evals/split_v4.json`），id 与 v5 的 dev 相同。**边界**：v4 时代 dev 120 中有 40 条与 train 重合，v5 已把这 40 条从 train 移除，因此 v5 的 train 与 dev 120 严格不重合；但 v5 的构造参考了 dev 120 的错例，dev 120 只能当同口径对比与回归信号，不是泛化估计。来源：`evals/split_v5.json`、`evals/leakage-check-v5.json`、`evals/test2-report.md`。

test2 覆盖：投诉 13/55（23.6%）、urgency 高 25 / 中 19 / 低 11、product 为 null 17/55（30.9%）。train 的投诉类从 v2 的 11/110（10.0%）升到 v3 的 22/122（18.0%），类别偏斜有缓解但仍未平衡。来源：`evals/cases_v3.jsonl`、`evals/split_v2.json`、`evals/split_v3.json`。

## 泄漏检查

方法分四层：原文归一化后精确匹配；order_id 与 customer_name 精确匹配；字符 2-gram 与 3-gram Jaccard；product 重合作为信息性统计。阈值是 Jaccard 大于等于 0.85 判疑似泄漏，0.60 至 0.85 判模板相近待复核。

| 对比 | 原文重合 | 订单号重合 | 姓名重合 | 疑似泄漏 | 模板相近 | product 重合 |
|---|---|---|---|---|---|---|
| train vs test2 | 0 | 0 | 0 | 0 | 0 | 23 |
| train vs dev2 | 0 | 0 | 0 | 0 | 0 | 12 |
| train vs valid | 0 | 0 | 0 | 0 | 0 | 13 |
| new dev80 vs train | 0 | 0 | 0 | 0 | 0 | 31 |
| new dev80 vs test2 | 0 | 0 | 0 | 0 | 0 | — |
| new dev80 vs valid | 0 | 0 | 0 | 0 | 0 | — |

判定 PASS。v5 的 `evals/leakage-check-v5.json` 同样 PASS：train 302 对 dev 120 / valid 40 / test2 55 / dev2 20 的原文、订单号、姓名重合均为 0，文本疑似泄漏 0；模板相近与 product 重合只作信息性统计。v3 最高相似对为 c161 与 c121，2-gram Jaccard 0.485、SequenceMatcher 0.731，两条都是保修期咨询模板，但产品不同（路由器与显示器）。week8 新增 80 条与 train 最高相似对为 c247 与 c027：3-gram Jaccard 0.157、2-gram Jaccard 0.289，均低于 0.60 的模板复核线；SequenceMatcher 0.615 只是参考指标，且原文不重合。与 test2/valid 的原文、订单号、姓名重合均为 0。train 内部有两组同名不同单（何静 c013/c048，邓超 c020/c051），不与任何测试集重合。来源：`evals/leakage-check-v3.json`、`evals/leakage-check-v4.json`、`evals/leakage-check-v5.json`。

## 已知限制

- 只覆盖字面与 n-gram，未做语义等价改写检测；
- 标签为单人按指南判定，未做第二人复核，边界口径仍有争议风险；
- train 投诉占比 18.0%，仍低于 test2 的 23.6%，不能按平衡样本解释类别指标；
- test2 55 条已于 2026-11-03 一次性消耗（`test2_consumed: true`），不再 sealed；其 held-out 结果只覆盖当时冻结的 0.5B 配置，不能用于后续 4B 选型或调参；
- v5 的 240 条新增是按“失败模式配比 + 改写 dev 错例”构造，dev 120 与 test2 上的同类模式增益存在乐观偏差；summary 目标在 v5 里写了具体诉求，但 test2 仍显示 summary 退化，说明“写法具体”不等于模型能学会；
- dev 120 的绝对值仍不是泛化估计：v5 已消除 train 与 dev 的字面重合，但构造过程参考了 dev 错例；
- 新增 80 条为单人标注，且刻意提高难度（51/80 为 hard），其绝对准确率不能与旧 dev 40 直接比较。
