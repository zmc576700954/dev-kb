# LoRA 首轮评测结果

> 1 epoch adapter 与基座在 dev2 20 与旧 dev 40 上各跑 5 次：格式缺陷更少，但准确率没有稳定提升，dev2 方向为负而统计上不能判定，耗时增加约四成，因此不采用为默认。

## 评测配置

- 基座 Qwen2.5-0.5B-Instruct；LoRA adapter 为 `data/processed/lora-epoch1-adapter/`。
- v4 提示词加后处理；outlines 1.3.3 约束解码；MPS、bf16。
- 注意：这 5 次没有传 `do_sample`，实际沿用模型 `generation_config.json` 的采样配置（T=0.7、top_p=0.8、top_k=20），不是 greedy。因此下表是 5 次随机采样的均值与极值，不是 5 次同配置复现。week4 已修正，见文末口径修正。
- dev2 用 `evals/cases_v2.jsonl` 与 `evals/split_v2.json`；旧 dev 40 用 `evals/cases_v2.jsonl` 与 `evals/split.json`。
- 每个配置 5 次独立进程，报告 5 次均值与极值，不挑单次。

## 确定性缺陷（5 次均值，样本 / 字段）

| 集合 | 配置 | raw 占位符 | raw 非法订单号 | raw 姓名等于订单号 | final 三类合计 |
|---|---|---|---|---|---|
| dev2 | 基座 | 6.8 / 7.6 | 0.8 | 0 | 0 |
| dev2 | LoRA | 0.4 / 0.4 | 0.2 | 0 | 0 |
| dev40 | 基座 | 15.8 / 21.8 | 8.6 | 0.6 | 0 |
| dev40 | LoRA | 3.2 / 4.2 | 2.6 | 0.2 | 0 |

raw 是未经过当前后处理的模型输出，final 是同一 run 经后处理后的输出。LoRA 确实减少了 raw 缺陷，但 final 在两种配置下都清到 0，端到端没有额外收益。

## 结论

- 没有可判定的提升。dev2 全字段低 0.100、结构字段低 0.040（n=20，配对 MDE 约 0.29–0.34）；dev40 全字段高 0.025、结构字段高 0.010（n=40，配对 MDE 约 0.23），5 次区间与基座大幅重叠，不能当提升。week4 配对检验显示两组都不显著，见文末口径修正。
- 字段层面是结构性交换：product 升 0.080（dev2）/ 0.130（dev40），issue_type 升 0.050 / 0.035；customer_name 降 0.070 / 0.075，urgency 降 0.070 / 0.030，order_id 持平 / 降 0.035，summary 降 0.170 / 持平。
- 格式缺陷只在 raw 阶段减少，当前后处理已把三类确定性缺陷清到 0，所以不能把缺陷下降算作准确率收益。
- 平均单条耗时从 0.600 s 升到 0.848 s（+41%），旧 dev 40 从 0.558 s 升到 0.796 s（+43%）。
- 综合取舍是不把该 adapter 设为默认，继续用基座加 outlines 加后处理；理由是“无可判定收益 + 约四成耗时”，不是“LoRA 被证明更差”。week8 未重训 LoRA，本页结论仍只覆盖 n=20/40。来源：`evals/week5-report.md`、`kb/kaiwu/99-归档/02-多seed重验结论.md`。

## 波动与可复现性

逐次全字段值：

| 配置 | r1 | r2 | r3 | r4 | r5 |
|---|---|---|---|---|---|
| 基座 dev2 | 0.200 | 0.250 | 0.200 | 0.300 | 0.200 |
| LoRA dev2 | 0.050 | 0.200 | 0.100 | 0.100 | 0.200 |
| 基座 dev40 | 0.300 | 0.575 | 0.325 | 0.300 | 0.475 |
| LoRA dev40 | 0.425 | 0.475 | 0.400 | 0.425 | 0.375 |

MPS 不是逐位可复现，基座 dev40 单是 5 次就在 0.300 至 0.575 之间波动。week4 诊断确认这组波动来自 outlines 未关闭采样，不是硬件随机；修复为 greedy 后，MPS 完整 dev40 两次 40/40 条输出一致。训练侧只跑了 1 个 adapter，权重本身没有重复训练，因此训练波动仍未确认。

## week4 口径修正

- 旧 5 次是随机采样（`do_sample` 未传，沿用模型 generation_config），不是 greedy 重复测量；上表均值/极值只作历史记录。
- 用 `evals/paired_stats.py` 对旧 5 次逐组做 McNemar 精确检验：dev2 p 为 0.375、1.000、0.625、0.289、1.000；dev40 p 为 0.267、0.424、0.549、0.267、0.424，全部大于 0.05，**不能判定 base 与 LoRA 有差异**。
- greedy 重跑后同样不显著：dev2 基座 0.250 对 LoRA 0.200，p=1.000；dev40 基座 0.450 对 LoRA 0.575，p=0.267。
- 因此“dev2 反而下降”应改为“方向为负但样本量不足以判定”；不采用 adapter 的理由是“无稳定收益 + 约四成耗时增加”，不是“显著更差”。
- 细节见 [评测稳定性与统计检验](../03-评测体系/03-评测稳定性与统计检验.md) 与 [评测波动诊断与统计口径](../07-决策日志/05-评测波动诊断与统计口径.md)。
