# 项目目标与路线

> kaiwu 的目标是在 Apple Silicon 单机上把客服工单字段抽取做到可复现、可评测、可微调。当前默认模型为 Qwen3-4B-Instruct-2507 MLX 4-bit（2026-11-03 由 0.5B 切换），已完成正式 LoRA 首轮验证与 test2 一次性验收；4B LoRA 于 2026-11-04 实测训练发散，尚未采纳 LoRA 为默认。

## 项目定位

本工作区做小模型的结构化抽取实验：输入一段客服对话，输出 6 个字段（customer_name、product、issue_type、urgency、order_id、summary）。默认基座为 Qwen3-4B-Instruct-2507 MLX 4-bit（本地 2.1 GB，许可 Apache-2.0）；Qwen2.5-0.5B-Instruct（953.3 MB，bf16）保留为历史基线，可通过 `--model-path` 显式指定。模型统一由 `config/models.json` 注册、`scripts/model_registry.py` 解析。来源：`config/models.json`、`evals/model-selection-report.md`、`docs/env.md`。

## 硬件与运行边界

单机 Apple M5 Pro、48 GB 统一内存、macOS 26.5.1 arm64，使用 MPS 后端。本机没有 CUDA，因此 bitsandbytes、flash-attn、vLLM、DeepSpeed 均未安装，标准 QLoRA 脚本不可直接复用。来源：`docs/env.md`。

## 当前结论

- 历史 milestone-1 冻结数字：旧 test 20 全字段 0.300、结构字段 0.400；outlines 配置为 0.250 / 0.283。该集合后来降级为 dev2，数字仅作历史参照。来源：`evals/test-milestone-1-report.md`。
- 当前 test2 55 条已于 2026-11-03 一次性消耗：基座全字段 0.182、结构字段 0.255；LoRA 三 seed 为 0.291/0.382/0.309，仅 seed 1 过预设判定线。此后 test2 降级为回归集（`test2_consumed: true`）。来源：`evals/test2-report.md`、`evals/split_v5.json`。
- 抽取准确率要带样本量读：旧 dev 40（简单样本）上 bf16 + outlines 为全字段 0.450、结构字段 0.475；week8 扩到 dev 120（其中 80 条为新增难样本）后为 0.267 / 0.333。下降主要来自样本变难，两组不能直接比较，也不能把 0.267 当泛化估计。来源：`evals/week8-report.md`。
- bf16 + outlines 与 MLX 4-bit + 约束在 dev 120 上为 0.267 对 0.292（全字段）、0.333 对 0.350（结构字段），McNemar p=0.690 / 0.845，差值低于配对 MDE 0.113 / 0.115，**不能判定谁更准**；MLX 的延迟与磁盘优势是真实工程收益。来源：`evals/week8-report.md`。
- 检索在 60 条语料、dev 120 下（week8 历史口径）recall@3 为 BM25 0.8917 / 向量 0.8333 / RRF 0.8750，不再饱和；RRF 显著优于纯向量（recall@1 +15.8pp，p=2.1e−05），相对纯 BM25 仍不能判定（+0.8pp，p=1.000）。**当前 v9 为 BM25 0.7833 / 0.9000 / 0.8361，RRF 0.7917 / 0.8583 / 0.8222**（2026-11-05）。来源：`evals/week8-report.md`、`evals/baseline.json`。
- LoRA 首轮 1 epoch 在 dev2 20 与旧 dev 40 上都没有可判定的提升：5 次区间大幅重叠，配对 p 全部大于 0.05，差值低于 MDE，耗时增加约四成。结论是“当前样本量下不可评估”，不是“被证明无效”。week8 未重训 LoRA，该结论只覆盖 n=20/40；week9 用 v5（train 302）重训后 dev120 增益可判定，但 test2 仅 1/3 seed 过线，见下节。来源：`evals/week5-report.md`、`evals/tuning-report.md`、`evals/test2-report.md`。
- 确定性缺陷（占位符、非法订单号、姓名等于订单号）在当前后处理下 final 均为 0；raw 阶段的缺陷条数变化只能说明后处理作用，不能当准确率收益。来源：`evals/week3-report.md`。
- 2026-11-03 模型选型（基座对基座，dev120 n=120）：Qwen3-4B-Instruct-2507（MLX 4-bit，2.29 GB）全字段 0.5417，相对 Qwen2.5-0.5B 的 0.2917 为 +25.0 pp，McNemar p=3.6e−05、95% CI [0.1417, 0.3583]、超配对 MDE 0.1631；Qwen3-8B 同分（Δ=0、p=1.0）但延迟 1.8 倍、磁盘 2 倍，只作备选。该差值混合参数规模与模型代际，不能全归因于“参数更多”，也不能与 0.5B LoRA 增益混算。**默认已于同日切换到 4B MLX 4-bit**，门禁基线随 dev120 重跑为全字段 0.542 / 结构字段 0.617（n=120，单次 greedy；历史，已废弃）；8B 权重已删除。此后经 prompt、gold、标尺与两遍生成，当前 v9 为 0.833 / 0.867（2026-11-05，详见仓库根目录 `docs/handover-2026-11-05.md`）。来源：`evals/model-selection-report.md`、`evals/baseline.json`、[模型选型](../06-微调与训练/08-模型选型.md)。
- 2026-11-04 换任务第一阶段（政策判定，n=120）：4B 基座在 BM25 top-3 档 joint 0.7333、全 60 条政策档 0.6417、关键词规则 0.1833；按预设判据落在 0.65–0.80 的“待定”区间，错误集中在 policy_id，decision 三类未塌缩。本轮只造题与测基线，未训练。来源：`evals/policy-task-bootstrap-report.md`、[任务定义与难度基线](../09-新任务-政策判定/01-任务定义与难度基线.md)。
- 2026-11-04 检索优化（test 120）：最佳为 RRF（BM25+bge，1:1，k=60）+ 原文查询，recall@3 103/108 = 0.9537、MRR 0.8244（配对 McNemar p=0.0039）；接入 4B 后 joint 0.7333→0.7750（93/120，配对 p=0.3323，不显著），差 1 题未过 0.78。结构化字段查询与近义扩展均使检索变差，正式配置不启用。27 条 joint 失败中仅 5 条源自检索，13 条是候选内选错，瓶颈已转到模型判别；未训练。来源：`evals/policy-retrieval-report.md`、[检索优化与瓶颈诊断](../09-新任务-政策判定/02-检索优化与瓶颈诊断.md)。
