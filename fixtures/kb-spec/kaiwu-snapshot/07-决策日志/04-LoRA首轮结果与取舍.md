# LoRA 首轮结果与取舍

> 2026-11-03 决定不把 1 epoch LoRA adapter 设为默认，继续用基座加 outlines 加后处理；理由是准确率无稳定收益、dev2 方向为负但统计上不能判定、耗时增加约四成。week4 用配对检验修正了“dev2 明显下降”的表述，决策本身不变。

## 背景

week2b 只跑了 20 步 smoke，未验证效果。week3 按计划用 v3 数据（train 122、valid 20）跑了 1 epoch、有效 batch 8、max_len 768 的 PEFT LoRA，然后在 dev2 20 与旧 dev 40 上与基座同配置各评测 5 次。adapter 与训练数字见微调配置与冒烟结果，评测细节见 LoRA 首轮评测结果。

## 备选方案

| 方案 | 证据 | 取舍 |
|---|---|---|
| 采用 adapter 为默认 | dev2 全字段 0.130 对基座 0.230，结构字段 0.260 对 0.300；dev40 0.420 对 0.395，区间重叠；配对 McNemar p 全部大于 0.05；耗时 +41% 至 +43% | 否 |
| 继续用基座加 outlines 加后处理 | 准确率不低于 adapter，格式由约束解码与后处理保证，耗时更低 | 采用 |
| 追加 2 至 3 epoch 再判断 | 1 epoch 不足以证明 LoRA 无效，但本轮没有任何方向的稳定收益；需要 valid 监控与多个训练 seed | 留到下一轮 |

## 决策

不采用首轮 adapter。它不是“被证明无效”，而是“在当前证据下不值得设为默认”：准确率没有可判定的提升（n=20/40，配对 MDE 约 0.23–0.34，差值全部低于门槛），dev2 方向为负但 n=20 下配对 McNemar p=1.000、不能判定，推理成本增加四成，而它唯一更少的 raw 格式缺陷已经被后处理覆盖。week8 扩 dev 与语料时没有重训 LoRA，本决策仍只覆盖 n=20/40。

week4 补充：旧 5 次评测实际是 outlines 未关闭采样的结果，greedy 重跑后 dev2 基座 0.250 对 LoRA 0.200（p=1.000）、dev40 0.450 对 0.575（p=0.267），仍全部不显著。因此本决策的依据从“dev2 明显下降”改为“无稳定收益 + 约四成耗时”，不写成“显著更差”。

## 后果

- 默认推理仍是基座、v4 提示词、outlines 约束解码与后处理；（**2026-11-03 模型切换**：基座改为 Qwen3-4B-Instruct-2507 MLX 4-bit，outlines 由枚举白名单似然裁决替代。）
- adapter 保留在 `data/processed/lora-epoch1-adapter/`，不合并、不接入默认评测；
- 不因为 dev2 方向为负就回头调 LoRA 超参：dev2 是旧 test，且该差异统计上不能判定；继续按它调参会把回归集变成第二个训练集；
- test2 55 条在本轮（week4）保持 sealed，没有运行任何 test2 评测；**2026-11-03 已完成一次性 held-out 验收，此后仅作回归**，见 [test2 验收结论](../06-微调与训练/07-test2验收结论.md)。
- 下一轮若继续微调，先定好 valid 监控与训练 seed 数，再决定是否只跑一次 dev 对比。

## 什么时候重新评估

- 追加 2 至 3 epoch，并在 valid 20 上记录 loss 与早停点；
- 至少跑 2 至 3 个训练 seed，确认训练侧波动，而不是只测推理波动；
- 只有在 product 与 issue_type 的提升稳定、且 customer_name、urgency、summary 不回退时，才考虑把 adapter 设为候选；
- 候选固定后，test2 只在预先写好的里程碑配置上跑一次，不因结果回调参数。
