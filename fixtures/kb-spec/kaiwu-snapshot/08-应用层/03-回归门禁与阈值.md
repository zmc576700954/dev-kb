# 回归门禁与阈值

> 单入口 `scripts/run_regression.sh` 串联抽取评测、BM25 检索评测、知识库 strict 校验与泄漏检查，与 `evals/baseline.json` 对比，跌破配置阈值即打印 REGRESSION 并以退出码 2 结束。**当前基线是 v9（2026-11-05）、默认模型 Qwen3-4B-Instruct-2507 MLX 4-bit、样本量 120（dev 120）、语料 60 条、两遍生成（两条定向重试通道默认开启）**；v9 的 all-120 混合口径为全字段 0.833 / 结构字段 0.867 / JSON 1.000，对外主口径 new-90 为 0.800。历史基线：2026-11-03 的 4B 单遍口径 0.542 / 0.617（已废弃）、同日早先的 0.5B bf16（0.267 / 0.333，存档 `evals/baseline-0.5b.json`）、旧 40 条基线（0.450 / 0.475），三组口径不同，都不能与 v9 相减或混用。完整交接见仓库根目录 `docs/handover-2026-11-05.md`。

## 为什么需要门禁

Week6 之前每次验证都要手动跑四条命令，容易漏项；指标也没有"上一轮是多少"的对照，改动后只能凭印象判断好坏。门禁解决两个问题：固定一次跑全，且把"变坏"定义成可执行的判断，而不是口头结论。

## 入口与产物

- 入口：仓库根目录执行 `scripts/run_regression.sh`；写基线用 `--update-baseline`。
- 阈值配置：`evals/regression_config.json`，脚本内不出现数字阈值。
- 基线快照：`evals/baseline.json`。
- 每次产物：`evals/results/regression/` 下的抽取 JSON 与 manifest、检索 JSON、知识库 JSON、summary JSON 与完整日志。

## 固定口径

| 项 | 取值 |
|---|---|
| 数据 | `evals/cases_v4.jsonl` + `evals/split_v4.json` 的 dev 120 条 |
| 提示词 | v4 |
| 模型 | `qwen3-4b-instruct-2507-mlx-4bit`（注册表默认，`config/models.json`） |
| 约束解码 | MLX 枚举白名单似然裁决（`mlx-enum`，无 outlines） |
| 采样与种子 | greedy，seed 0 |
| 设备与精度 | MLX / 4-bit |
| 后处理 | 开启 |
| 重试通道 | `summary` / `product` / `customer_name` 定向重写默认开启（`--summary-retry`、`--field-retry` 均默认 True，`--no-summary-retry` / `--no-field-retry` 关闭）；`SUMMARY_RETRY=0` / `FIELD_RETRY=0` 时门禁脚本显式传 `--no-*`。关闭后分数不可与 v9 直接相减 |
| 检索 | BM25，top-3；语料 60 条（KB-001 至 KB-060） |

口径固定是为了让"基线对比"有意义；换口径必须显式更新基线，不能悄悄改脚本默认值。2026-11-03 两次变更都写进了 `baseline.json` 的 `change_date` / `note`：第一次是 week8 扩样本（dev 40→120、语料 30→60），第二次是默认模型从 0.5B bf16 + outlines 切到 4B MLX 4-bit（backend 与约束机制同时改变）。2026-11-04 至 11-05 又发生 6 个口径事件（summary 同义扩展、product 归一、两次 gold 校准、两条重试通道默认开启），每一步都单独锁基线 v5–v9；断点前后的数字不可直接相减，清单见仓库根目录 `docs/handover-2026-11-05.md` 第 3 节。

## 基线与阈值

| 指标 | v9 基线（4B MLX 4-bit，dev 120 / 语料 60，两遍生成） | 允许回退 |
|---|---|---|
| 全字段全对率（all-120 混合） | 0.833 | -0.05 |
| 结构字段全对率 | 0.867 | -0.05 |
| JSON 合法率 | 1.000 | -0.02 |
| customer_name / product / issue_type | 1.000 / 0.967 / 0.917 | 不设阈值 |
| urgency / order_id / summary | 0.983 / 1.000 / 0.956 | 不设阈值 |
| BM25 recall@1 | 0.7833 | -0.03 |
| BM25 recall@3 | 0.9000 | -0.02 |
| BM25 MRR@3 | 0.8361 | -0.03 |
| RRF recall@1 / MRR@3 / 主 gold（observe） | 0.7917 / 0.8222 / 0.6583 | 不阻塞 |
| 知识库 error / warning | 0 / 0 | 必须 0 |
| 泄漏检查 | PASS | 必须 PASS |

**cohort 口径**：old-30（n=30，5 字段，all_fields 0.933）、new-90（n=90，6 字段，all_fields 0.800，对外主口径）、all-120（n=120，混合口径：old-30 用 `structured_ok` 算 5 字段、new-90 用 `all_ok` 算 6 字段，`all_fields_scope="mixed"`，0.833）。all-120 的 0.833 不是统一基线；历史文档里的 0.750 也是混合口径，不能与 new-90 的 6 字段数比较。

**适用条件**：上表抽取项来自 `evals/results/regression/eval-mlx-v4-pp-dev-regression-20261105-003613.json`（n=120，单次 greedy，枚举裁决 + 两遍生成），检索项来自同次运行的 `rag-20261105-003141.json`。2026-11-03 的旧表（0.542 / 0.617、BM25 0.775 / 0.900 / 0.8333）来自 `eval-mlx-v4-pp-dev-regression-20261103-224238.json`，是**历史，已废弃**，不能与 v9 相减。旧 0.5B 基线（0.267 / 0.333）写在 `evals/baseline-0.5b.json`，是**换模型前**的同一 dev 120 结果，不能与 0.542 或 0.833 相减当作模型能力变化之外的效应（模型、精度、约束机制、gold、标尺与重试通道都变过）。

阈值不是统计推导，而是按样本量的经验设定：120 条时 1 条 case 约等于 0.0083，-0.05 约等于 6 条；40 条时 1 条等于 0.025，-0.05 约等于 2 条。阈值只用于拦截明显回退，不用于宣布小幅波动是真实提升；小于 MDE（n=120 时约 0.09–0.11）的差异不能当结论。

## 观察级指标（observe）

不是所有指标都适合立刻阻塞发布。配置里把检索指标分成两级：

- 阻塞级（`retrieval.thresholds`）：BM25 的 recall@1、recall@3、MRR@3，跌破阈值即 REGRESSION、退出码 2。
- 观察级（`retrieval.observe`）：RRF 的 recall@1、MRR@3、主 gold 排第一。只把当前值、基线与 delta 打进日志和 summary，不参与退出码。

回归脚本会在检索步骤后追加一次 RRF 计算（不跑配对检验），结果供对比脚本读取；RRF 计算失败只记一条日志，不改变门禁结论。这样实验路径的漂移可见，但不会因为未定型的方案阻塞发布。虽然 week8 已在 dev 120 上确认 RRF 显著优于纯向量，但它对纯 BM25 仍不能判定，因此保持 observe，不升级为阻塞。

实测：RRF 基线人为抬高 0.04 / 0.025 / 0.075 后，三项都打印 `observe（不影响退出码）`，总判定仍为 PASS、退出码 0；同时把 BM25 recall@1 基线抬高 0.05 后，该项打印 REGRESSION、退出码 2。证据在 `evals/results/regression/drift-observe.txt` 与 `drift-block.txt`。

## 实测

**v9 锁后复跑（2026-11-05）**：退出码 0，所有阻塞指标 delta 为 0（BM25 0.7833 / 0.9000 / 0.8361），三个 observe 指标 delta 也为 0（RRF 0.7917 / 0.8222 / 0.6583），知识库 0 error 0 warning，泄漏 PASS，总耗时 **282 s**；日志 `evals/results/regression/gate-v9-confirm.log`。同一口径下抽取为贪心解码，可复现。

**历史：2026-11-03 重设基线后**，一次完整运行退出码 0，所有阻塞指标 delta 为 0，判定 `PASS（无指标回退，门禁通过）`；日志在 `evals/results/regression/run-20261103-145800.log`。单步耗时为抽取约 26 s、检索约 5 s、RRF 约 7 s、知识库与泄漏 1 s 以内。

**历史：2026-11-03 模型切换后的实测**（已废弃，勿引用为当前值）：首次 `run_regression.sh --update-baseline` 的抽取步骤成功（4B MLX，120 条，173.5 s），随后检索步骤访问 `huggingface.co` 连续超时、在写入基线前中止。改用 `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1` 完整复跑后 PASS：抽取 0.542 / 0.617 / 1.000，检索 BM25 0.775 / 0.900 / 0.8333，知识库 0 error 0 warning，泄漏 PASS（v5 检查，精确重合 0、文本疑似泄漏 0），总耗时 187 s，日志 `evals/results/regression/run-20261103-223941.log`、汇总 `summary-20261103-223941.json`。这组是 v9 之前的历史基线。

故障注入：把基线全字段率改成 0.60 后重跑对比，只有该项被判 REGRESSION，退出码 2，其余指标仍为 ok。说明阈值判断与退出码链路有效。证据在 `evals/results/regression/fault-injection.txt`。

## 局限与使用约定

- 抽取结果会受 MPS 状态与运行环境影响；门禁只能拦住超过阈值的回退，拦不住 1 条以内的抖动。
- 检索门禁只覆盖 BM25；RRF 属于实验路径，暂不设门禁，避免未定型的方案阻塞发布。
- 新增指标时先写进配置再写进脚本，保持"阈值唯一来源"。
- 任何一次"更新基线"都要在提交说明或周报里写原因，否则后人无法区分"口径变了"与"效果变了"。
