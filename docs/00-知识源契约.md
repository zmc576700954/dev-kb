# 知识源接入契约

> 本文说明 dev-kb 的知识源接入契约：为什么需要它、声明长什么样、规则怎么判、新增一种知识源要做什么。

## 1. 它解决什么问题

检索器每接入一种新的知识源，通常要写一段新代码：新的切块方式、新的字段含义、新的路径约定、新的查询提示。这些特例散在检索器里，源一多就互相干扰——**改一个动全部**。这是"兼容面爆炸"，不是功能缺失。

契约把这件事反过来做：**先规定"任何知识源接入时必须交代什么"，检索器只认这些交代，不认具体是哪种库**。

因此：

- 知识源**没有类型枚举**。不存在"Markdown 库 / 代码库 / FAQ 库"这类枚举值。
- 知识源声明自己**提供哪些结构字段**，检索器按声明消费，缺什么即降级。
- 新增一种知识源**不需要改检索器**，只需要写一份声明。

契约不是文档质量评分。措辞、篇幅、链接数量、表格样式都不在契约范围内——那些规则会产生大量误报却不改善检索。

## 2. 声明模型

声明写在 `projects.yaml` 的知识源条目里。注册表只放**契约**（几十行以内），调优表另放按源独立的文件。

| 字段 | 含义 | 缺省 |
|---|---|---|
| `provides` | 声明本源提供的可选结构字段 | `[]`（什么都不提供，全部降级） |
| `content_roots` | 内容边界（相对项目根）；`["."]` 表示全库 | `[]`（**R-01 会报错**：边界必须显式声明） |
| `entry_docs` | 入口文档（相对项目根） | `[]` |
| `intent_map` | 中文意图 → 本库路径模式 | `{}` |
| `roles` | 路径通配 → 文档角色 | `{}` |
| `terms` / `tuning` | 术语别名与调优表文件 | 无 |

### 可选结构字段（契约字段集）

| 字段 | 语义 | 从哪来 |
|---|---|---|
| `heading_path` | 标题链（祖先标题 → 自身标题） | 切块时自动提取，文档类知识源天然有 |
| `category` | 所属分类 | **路径首段自动推导**（`src/app/Pay.php` → `src`） |
| `doc_role` | 文档角色（index / entry / faq / reference / guide） | 声明的 `roles` 映射 |
| `aliases` | 该块正文里出现的术语及其别名 | 声明的 `terms` / `tuning` 别名表 |

`category` 对所有知识源通用：代码库自动得到 `src`/`app`/`docs`，文档知识库得到 `01-业务概览` 这类一级目录。取路径首段原样、不做前缀剥离，这样它与 path 子串匹配用的是同一份字面量。

### 调优表

别名、意图映射、角色三类表放在 `tuning/<source>.yaml`。**约定优于配置**：没显式写
`tuning:` 时，工具会自动找 `tuning/<源名>.yaml`——这样调优表可以随仓库分发，
不必在每台机器的注册表里重复引用一遍。

```yaml
aliases:
  LoRA: [lora, 低秩适配, 轻量微调]
intent_map:
  部署: ["09-部署与生态"]
roles:
  "README.md": index
  "99-索引与排序/*": index
```

注册表用 `tuning: [tuning/<source>.yaml]` 引用。**注册表必须保持小**（红线：每个源 ≤ 30 行）——调优表会长大，它属于表不属于契约。

## 3. 规则

7 条，全部可机械判定。error 的判据是：**缺失会造成可观测的检索退化，且能机械判定、不会误报**。

| ID | 条文 | 级别 | 适用范围 |
|---|---|---|---|
| R-01 | 知识源必须声明 `content_roots`（或显式声明全库）；未声明的路径不进索引 | error | 全部 |
| R-02 | 声明 `provides` 含 `heading_path` 的源，其 document 块标题链覆盖率须 ≥ 95%，低于阈值该能力自动降级 | error | 声明了 heading_path |
| R-03 | `intent_map` 中每条路径片段必须能匹配到本库里的某个路径 | error | 有意图映射 |
| R-04 | 声明了分类结构的源必须声明 `entry_docs`，且每个入口文档真实存在 | error | 声明了 category |
| R-05 | document 块缺标题链时检索可信度下降，应补齐标题层级 | warning | 声明了 heading_path |
| R-06 | `aliases` 中每个术语都必须在至少一个块的正文里出现 | warning | 声明了 aliases |
| R-07 | `provides` 中出现的字段名必须属于契约字段集 | error | 全部 |

**不适用不是发现。** 源没声明对应字段时，相关规则直接跳过——这是同一个契约能套在文档型知识库、代码仓库和未来任何形态上的原因。

**R-03 的口径与检索一致。** `intent_map` 的值是**路径片段**（检索时用它做
`path LIKE %片段%`），不是字面路径。所以判据是"这个片段能匹配到本库的某个路径"——
否则 `"migrations"` 这类片段会被误判为不存在（它实际匹配 `database/migrations/…`）。
指向不可检索内容的片段（目标目录被排除在索引外）同样算缺陷：它占着通道的位置却
永远命中不了东西。

规则分两层：**声明层**（R-01 / R-03 / R-04 / R-07）只读文件系统与注册表；**索引层**（R-02 / R-05 / R-06）需要 `meta.db`。没有索引时索引层规则不适用——"还没建索引"不等于"没有标题链"。

## 4. 索引侧的落点

契约不是纸面约定，它在索引里有对应字段。`chunks` 表：

```
project, path, source_type, language, symbol,
heading_path, category, doc_role, aliases,     ← 契约字段
start_line, end_line, content, embedded
```

- `heading_path` 进 `chunk_fts` 的可检索文本（与正文同等权重），同时另有一张 `chunk_headings` 索引支撑**独立的标题链召回通道**——独立通道的意义是可单独调权、单独归因，评测里能看到它贡献了多少 recall。
- `category` / `doc_role` / `aliases` 由同步时按声明填入。契约字段的**唯一事实源是 SQLite**，向量库 payload 不复制一份（payload 只存标识与定位信息）。

存量索引可用 `sync_cli --backfill` 回填契约字段、`sync_cli --rebuild-fts` 重建索引，**不重扫源文件、不重算向量**。

## 5. 检索侧怎么用

| 机制 | 作用 | 权重 |
|---|---|---|
| 标题链独立通道 | 只匹配文档标题里的词（**AND 精确匹配**，不做宽松降级） | 0.7（`DEV_KB_HEADING_WEIGHT`） |
| 术语别名通道 | 查询词命中声明的别名时，把查询扩展成 canonical 词 | 1.0（`DEV_KB_ALIAS_WEIGHT`） |
| 意图映射路径提示 | 知识源声明的"中文意图 → 本库路径" | 0.7（`DEV_KB_INTENT_HINT_WEIGHT`） |

原全局硬编码路径表（`_PATH_HINTS`）已被**彻底取代并删除**：它的条目按源分发到
各库的 `tuning/<source>.yaml`，并逐条用本库实际内容过滤（片段匹配不到任何路径的
丢弃）。取代它花了三轮测量——先按源写声明（比全局表差）、再叠加（更差，稀释）、
最后发现关键差别是**片段的粒度**：全局表用 `api`、`Auth` 这类短片段，能同时匹配到
文件名（`ApiController.php`），按目录写的映射匹配不到。
| 结构可信度降权 | 声明了标题链却缺标题链的 document 块降权 | 0.7（`DEV_KB_STRUCTURE_TRUST`） |

四个权重都可用环境变量覆盖，便于逐通道做评测归因；`DEV_KB_HEADING_FALLBACK=1` 可
临时打开标题通道的宽松降级（实测有害，见 [evals/README](../evals/README.md)）。

## 6. 新增一种知识源要做什么

1. 在 `projects.yaml` 加一条：路径、`provides`、`content_roots`、`entry_docs`。
2. 需要精细调优时加 `tuning/<source>.yaml`（别名、意图映射、角色）。
3. 跑 `sync_cli` 建索引，`contract.cli validate <name>` 确认声明自洽。
4. 如果这类知识源需要**新的结构字段**（不在契约字段集里），那是契约要扩展的信号：先加进字段集，再加列、再加检索用法——不要在检索器里为它开特例。

## 7. 边界

契约**不做**的事：文档增删改、提案审批落盘、批量迁移、文档质量评判（措辞/字数/链接数/表格尺寸）、文档生命周期治理（状态/复核周期/归档标注）、文档 frontmatter 解析。

其中"文档增删改"在 2026-11-15 被明确移出本项目范围——它属于代码开发与知识库维护的工作，不属于检索问答 Agent。
