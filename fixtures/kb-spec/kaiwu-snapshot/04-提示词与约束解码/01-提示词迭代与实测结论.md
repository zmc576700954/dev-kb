# 提示词迭代与实测结论

> 记录 v0 到 v4 的提示词改动、dev 与 test 上的实测变化，以及为什么提示词阶段的收益已经接近上限。

## 版本与改动

| 版本 | 主要改动 |
|---|---|
| v0 | 基线 schema 描述，无规则、无示例 |
| v1 | 补充字段规则与枚举解释 |
| v2 | v1 加 2 条 few-shot（中文信封格式） |
| v3 | v2 加完整 Pydantic JSON schema |
| v4 | v1 加姓名位置规则与 3 条 few-shot |
| v4+pp | v4 加确定性后处理（枚举映射、姓名清洗、summary 兜底） |

提示词在 `scripts/prompts.py`，后处理（`postprocess_ticket`）在 `scripts/extract.py`，调用入口同在该文件。

## dev 20 实测（n=20，提示词迭代记录）

| 配置 | 全字段 | 结构字段 | JSON 合法 | 备注 |
|---|---|---|---|---|
| v0 | 0.050 | 0.050 | 1.000 | 偏短，几乎全错 |
| v0+pp | 0.050 | 0.050 | 1.000 | 后处理无法补救缺字段 |
| v1 | 0.100 | 0.100 | 0.650 | 规则过长，JSON 合法率下降 |
| v2 | 0.300 | 0.300 | 0.900 | 加示例后明显回升 |
| v3 | 0.150 | 0.150 | 0.950 | 塞完整 schema 后准确率反而下降 |
| v2+pp | 0.300 | 0.300 | 0.950 | 枚举同义映射修正 JSON |
| v4 | 0.450 | 0.450 | 0.950 | 姓名规则加 3 条 few-shot |
| v4+pp | 0.550 | 0.550 | 1.000 | dev 20 上最好 |

来源：`evals/week1-report.md`。同一配置在 40 条 dev 上的全字段为 0.400，说明样本量变化会显著改变绝对值。

**适用条件与样本量**：这张表的每一格都只在 n=20 上成立，用于比较同一批 case 上各版本的相对变化，不能跨数据集比较绝对值。week8 把 dev 扩到 120 条（旧 40 + 新增 80，其中 51/80 标为 hard）后，bf16 + outlines 的全字段为 0.267、结构字段为 0.333；下降主要来自样本变难与样本量，不是提示词退化，也不能把 0.450 或 0.550 当当前模型水平。来源：`evals/week8-report.md`。

## 干净 test 20 实测

| 配置 | 全字段 | 结构字段 | JSON 合法 | 平均耗时 |
|---|---|---|---|---|
| v0 | 0.050 | 0.050 | 1.000 | 0.40 s |
| v4+pp | 0.250 | 0.300 | 0.950 | 0.44 s |

v4+pp 的逐字段准确率：customer_name 0.70、product 0.75、issue_type 0.65、urgency 0.65、order_id 0.95、summary 0.85。来源：`evals/week1.5-report.md`。

## 关键结论

1. 规则写得越长，格式越容易坏：v1 把 JSON 合法率从 1.000 拉到 0.650，urgency 从 0.55 掉到 0.15。
2. few-shot 比继续加规则有效：v1 到 v2 的全字段从 0.100 升到 0.300。
3. 在提示词里塞完整 JSON schema 是负收益：v2 到 v3 从 0.300 降到 0.150，提示词从 518 字符涨到 1344 字符。
4. 后处理单独使用没有收益，但能把枚举同义写法规范成合法值，JSON 合法率从 0.900 升到 0.950。
5. 姓名规则（优先取“叫/名字是/我是”后的说法）把 customer_name 从 0.70 提到 0.90，全字段从 0.30 提到 0.45（n=20 同一批 case 内比较；绝对值不可跨数据集迁移）。
6. 在干净 test 上，v4+pp 只拿到 0.250，说明 dev 上的 0.550 含拟合成分（两者都是 n=20，且 test 20 后来降级为 dev2，只能当历史参照）。

## 失败模式

- 抽象服务名被写成品牌：把“你们这个会员服务”写成具体产品；
- 姓名出现在“X的订单”“X买的”里，模型只抓首个看起来像名字的词；
- urgency 的“尽快”“着急”没有被映射到高；
- issue_type 的“其他”与“业务咨询”边界不稳；
- summary 关键词覆盖不全，同义改写未命中。

来源：`evals/test-milestone-1-report.md`。
