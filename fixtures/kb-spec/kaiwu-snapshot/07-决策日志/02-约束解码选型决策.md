# 约束解码选型决策

> 2026-11-02 决定以 outlines 1.3.3 作为首选约束引擎，自写 FSM 保留为对照，非约束保留为基线；这是一个用格式稳定性换部分准确率的选择。

## 背景

目标是让输出稳定合法，同时不牺牲字段准确率。逐条验证可用方案后，transformers 5.22.1 没有 `guided_json`，传参会报 `model_kwargs` 未使用；llama.cpp 虽有 grammar 参数，但工作区没有 GGUF，也没有转换脚本，无法实测。可选项只剩 outlines、自写 FSM 与非约束。

## 备选方案

| 方案 | 格式 | 准确率（dev 40，n=40） | 耗时 | 结论 |
|---|---|---|---|---|
| 非约束 | JSON 1.00，但 4 条靠修复重试 | 0.425 / 0.475 | 0.36 s | 保留为基线 |
| outlines | JSON 1.00，首次全合法 | 0.325 / 0.350 | 0.58 s | 选为首选 |
| 自写 FSM | JSON 1.00，首次全合法 | 0.425 / 0.475 | 0.96 s | 保留为对照 |

准确率列是 n=40 旧简单样本的旧采样口径单次值，配对 MDE 约 0.23，0.10 量级的差异不能判定。week8 在 dev 120 上只用 bf16 + outlines 与 MLX 4-bit + 约束重测（0.267 / 0.292 全字段，差异 p=0.690、低于 MDE 0.113）；非约束与 FSM 未重跑，因此本决策的相对代价仍只覆盖 n=40。

## 决策

outlines 作为首选约束引擎，原因是本机实测可安装、可运行，JSON 合法率 1.00，枚举越界 0，耗时约为非约束的 1.6 倍。FSM 保留为对照，因为它在 dev 40 上不损失准确率，可以回答“约束本身是否改变分布”这个问题；代价是耗时约 2.7 倍。非约束保留为基线，因为它的准确率不低于约束方案，说明约束买到的是稳定性而不是精度。

## 后果

- 格式收益明确：占位符、非法订单号、姓名等于订单号三类缺陷在新后处理下清到 0，枚举越界从 5 降到 0；
- 准确率代价明确：dev 40 全字段从 0.425 降到 0.325，结构字段从 0.475 降到 0.350；test 20 全字段从 0.300 降到 0.250（均为 n=20/40 旧样本，不能当当前水平）；
- test 20 上 0.050 的差距在 n=20 下不能判定显著，但方向与 dev 一致，因此选型标注为“待复核”；
- week8 在 dev 120 上把 bf16 + outlines 做到全字段 0.267、结构字段 0.333、JSON 1.000；与 MLX 约束的差异不能判定，但**没有重跑非约束**，所以“约束买到稳定性而非精度”仍需在 dev 120 上补测；
- MPS greedy 跨进程不是逐位可复现，所有数字是单次点估计；
- 若后续扩到 40 至 60 条 sealed 数据，需要重新比较 outlines 与 FSM，再决定是否把 outlines 写死为默认。（**2026-11-03 后续**：test2 已消耗、默认模型已切到 4B MLX 4-bit；MLX 没有 outlines，等价机制是枚举白名单似然裁决，故本条不再作为待办。）
