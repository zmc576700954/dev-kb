# 约束解码取舍

> 对比非约束、outlines 与自写 FSM 三种解码方式在 dev 40 与 test 20 上的合法率、准确率与耗时，说明为什么保留两条路线而不是只留一条。

## 三种方案

| 方案 | 可用性 | 做法 |
|---|---|---|
| 非约束 | 始终可用 | greedy 生成，靠提示词要求 JSON，失败后最多一次修复重试 |
| outlines 1.3.3 | 本机实测可用 | 由 Pydantic 模型编译 JSON Schema，按 schema 做 token 掩码 |
| 自写 FSM | 纯 torch 实现 | 固定六字段骨架与枚举集合，逐步推进状态机 |

transformers 5.22.1 的 `generate` 没有 `guided_json`，传参会报 `model_kwargs` 未使用，因此内置约束路线不可用。llama.cpp 有 `--grammar`，但工作区没有 GGUF，也没有 `convert_hf_to_gguf.py`，未做实测，不算已验证方案。

## dev 40 实测（n=40，旧简单样本）

| 配置 | JSON 合法 | 首次合法 | 全字段 | 结构字段 | 平均单条 |
|---|---|---|---|---|---|
| 非约束 | 1.00 | 36/40 | 0.425 | 0.475 | 0.36 s |
| FSM | 1.00 | 40/40 | 0.425 | 0.475 | 0.96 s |
| outlines | 1.00 | 40/40 | 0.325 | 0.350 | 0.58 s |

逐字段对比（outlines 相对非约束）：customer_name 1.000 对 0.950，product 0.650 对 0.775，issue_type 0.750 对 0.825，urgency 0.650 对 0.750，order_id 持平 1.000，summary 0.455 对 0.636。outlines 的损失集中在 product、urgency 与 summary。

枚举越界：非约束 raw 有 5 例（“不急”“急”“立即”），FSM 与 outlines 均为 0。占位符、非法订单号、姓名等于订单号三类缺陷，在新后处理下三种方案都清到 0。来源：`evals/week2a-report.md`。

**适用条件与样本量**：本表是 n=40 旧简单样本上的单次点估计，n=40 的配对 MDE 约 0.23，表内 0.10 量级的方案间差异不能判定；它只用于比较三种解码方式的相对代价，不能跨数据集比较绝对值。week8 只重测了 bf16 + outlines 与 MLX 4-bit + 约束，在 dev 120 上分别为全字段 0.267 / 0.292、结构字段 0.333 / 0.350；**非约束与 FSM 没有在 dev 120 上重跑**，因此“约束不损失准确率”的结论仍只覆盖 n=40。来源：`evals/week2a-report.md`、`evals/week8-report.md`。

## test 20（现 dev2）实测

| 配置 | 全字段 | 结构字段 | JSON 合法 | 平均单条 |
|---|---|---|---|---|
| 非约束 | 0.300 | 0.400 | 0.95 | 0.40 s |
| FSM | 0.300 | 0.400 | 1.00 | 1.06 s |
| outlines | 0.250 | 0.283 | 1.00 | 0.65 s |

每种配置跑 3 次，报告给的是均值与区间。非约束与 FSM 的全字段都是 0.300 [0.300, 0.300]，outlines 是 0.250 [0.200, 0.300]。来源：`evals/test-milestone-1-report.md`。

这批 20 条后来成为 dev2。2026-11-03 用 v4 加后处理复跑 5 次（旧口径为采样），outlines 的全字段均值 0.230 [0.200, 0.300]、结构字段 0.300 [0.250, 0.400]、平均单条 0.600 s；上表 0.250 / 0.283 是 week2a 的单次值，不能与 5 次均值直接比较。来源：`evals/results/eval-hf-v4-pp-guided-dev2-s3-base-dev2-r1..r5-*.json`。

## 取舍结论

- outlines 是首选约束引擎：JSON 合法率 1.00，枚举 0 越界，耗时约 1.6 倍，代价可接受（n=40 旧简单样本；week8 在 dev 120 上仍保持 JSON 1.000）。
- FSM 保留为对照：在 dev 40 上不损失准确率，但耗时约 2.7 倍，适合作为“约束但不改分布”的参照（仅 n=40，未在 dev 120 重跑）。
- 非约束保留为基线：格式能靠重试补齐，准确率不低于约束方案，说明约束解码买到的是稳定性，不是精度（仅 n=40，未在 dev 120 重跑）。
- 在 test 20 上 outlines 的全字段低 0.050、结构字段低 0.117，样本量下不能判定显著，但趋势与 dev 一致，选型需要更多数据复核。
- **week4 修正**：以上 outlines 的 dev40/test20 数字是旧口径，实际没有传 `do_sample`，沿用模型 generation_config 的采样（T=0.7、top_p=0.8、top_k=20），不是 greedy；因此“跨进程不可复现”是采样造成，不是 MPS 硬件。修复为 `do_sample=False` 后，MPS greedy 完整 dev40 两次 40/40 条一致，greedy 基座 dev2 全字段 0.250、dev40 0.450。旧点估计只作历史对照。见 [评测稳定性与统计检验](../03-评测体系/03-评测稳定性与统计检验.md)。
