# 评测波动诊断与统计口径

> 2026-11-03 决定：把 outlines 评测固定为 greedy，每次写 manifest；默认继续用 MPS bf16，CPU float32 只作可选仲裁；所有配置对比改用配对检验与 Wilson/MDE，不再用单次点估计下结论。

## 背景

week3 的 dev40 基座 5 次全字段在 0.300 至 0.575 之间波动，最初怀疑是 MPS 非逐位可复现。week4 先审计 5 份结果的实际配置，再做同输入重复实验与跨通道对比。结果是配置一致，但 outlines 没有传 `do_sample`，沿用了模型自带的采样配置（T=0.7、top_p=0.8、top_k=20），5 次是随机采样而不是 greedy。修复后 MPS greedy 完整 dev40 两次 40/40 条输出一致。

## 备选方案

| 方案 | 证据 | 取舍 |
|---|---|---|
| 保留旧采样，用多次平均 | 采样方差大，10 条 case 10 次 0/10 逐字符一致；相同 n 下均值仍不稳 | 否 |
| 固定 greedy，MPS 作默认 | MPS greedy 10×10 一致，完整 dev40 两次 40/40 一致；单条 0.60 s | 采用 |
| CPU float32 作默认 | 全量 dev40 67.37 s 对 26.41 s，单条 1.63 s 对 0.60 s；与 MPS 3/40 条分数翻转 | 否 |
| CPU float32 作仲裁 | 确定性，但只 35/40 条 raw 与 MPS 相同，不是逐位复刻 | 保留为可选 |
| 继续用单次准确率比较 | n=20/40 的 MDE 约 0.23 至 0.37，week3 配对 p 全部大于 0.05 | 否 |

## 决策

- `scripts/guided_outlines.py` 默认 `do_sample=False`，并显式清空 temperature、top_p、top_k；
- `evals/eval.py` 增加 `--device`、`--precision`、`--seed`，默认 MPS、bf16、seed 0；
- 每次评测写 manifest（模型 revision/权重 hash、库版本、prompt hash、约束配置、数据 hash、seed、精度、规则版本、时间）；
- 默认评测口径是 MPS bf16 greedy；CPU float32 只用于仲裁或复现检查；
- 配置对比必须用 `evals/paired_stats.py` 的 McNemar、配对 bootstrap、Wilson 与 MDE；p 大于 0.05 写“不能判定有差异”。

## 后果

- week3 的 5 次 LoRA 对比是采样结果，不能当同配置重复测量；旧数字只作历史记录。
- 配对检验显示 dev2 与 dev40 的 base vs LoRA 都不显著；“dev2 明显下降”修正为“方向为负但不能判定”。
- 不采用 1 epoch LoRA 的决策不变，但理由改为“无稳定收益 + 约四成耗时增加”，不是“显著更差”。
- CPU 通道不会成为默认，因为它更慢且与 MPS 不是逐位一致；它只回答“这条差异是否可能来自后端数值”。
- test2 在本轮（week4）保持 sealed，没有 test2 评测；**2026-11-03 已一次性消耗**（`test2_consumed: true`），之后只能作回归集。

## 什么时候重新评估

- 如果后续要在 CPU 上做正式评测，先重跑 dev40 并接受它与 MPS 的 3/40 分数差，不要把它当复现；
- 如果换 torch、transformers、outlines 版本，重新跑 10 条 case × 10 次 greedy 一致性探针；
- 如果要比较两个新配置，先固定 greedy 与 manifest，再用配对检验；样本量不足时先扩 test2/dev，而不是反复调参；
- test2 只在候选配置写死后跑一次，并给 Wilson 区间。
